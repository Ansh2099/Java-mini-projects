ATTACK 1 [MAJOR] The top pick names Fortnox as an open market, but a ready AI order tool already sells on Fortnox's own marketplace
Where: Software table, Fortnox row: "No tool found (limited search)"; E1 f: "On Netvisor, Procountor and Fortnox, I found no dedicated tool"; Part 5 pick 1: "these ERPs have usable APIs and no built in agent or cheap tool that I found".
Problem: Fortnox's own integration marketplace lists "Qrisp Orderskanning" (https://www.fortnox.se/integrationer/integration/grossistlagret-i-sverige-ab/qrisp-orderskanning). It reads PDF orders and email with AI, matches the customer against the Fortnox customer register, learns articles automatically, lets a person review and approve, and then creates the order in Fortnox. It connects with one OAuth click and charges a fixed monthly price with unlimited orders. That is E1 for Fortnox, sold as a self serve tool. The task says: "If it is already solved by a built in feature or a cheap tool, reject it." The report's own lesson 4 says the same thing. Fortnox should have been rejected, not named in the top pick. It also means the report's "no tool found" checks for Netvisor and Procountor come from the same "limited search" and cannot be trusted as they stand. One search in Swedish found this. The user is told to go and sell into a market that already has a product built for exactly this job.

ATTACK 2 [MAJOR] The Sage 200 connector needs a paid Sage developer subscription. The report ignores this, so its budget and plan claims are unsupported
Where: Budget note: "For Sage 200, Fortnox, Netvisor and Procountor, API access runs on the client's own subscription"; Part 5 weeks 11 to 14: "Sage 200 ... adapter against a test company"; running cost: "This fits under $50 a month for your first clients."
Problem: Sage's own knowledge base says "Development with the Sage 200 API requires membership of the Sage 200 API Developer Programme". The SDK route needs the Sage ISV/Developer programme subscription as the minimum. It is a 12 month subscription, Sage announced a price increase from 1 August 2025, and it does not publish the fee (Sage KB "Sage 200 API Common Queries" and "Sage 50/200 UKI Developer Programme Renewal and upcoming price updates", both found in search). Sage 200 is sold on premise through resellers, so the team has no "test company" unless they pay for the programme or borrow a client's live system. The hard constraint is "Our budget is under 50 USD a month until we have revenue", and the lead European target breaks it before the first sale. The report never names this cost and only says "check each vendor's developer terms". The 16 week plan and the "$50 a month" claim both rest on an unchecked assumption.

ATTACK 5 [MAJOR] The report's own math shows the INR prices for small Indian firms do not pay for themselves
Where: I1 e: "the saving is about 3.5 hours a day, about ₹7,000 a month"; I1 g: "Small ... ₹20,000 to ₹40,000 setup, ₹3,000 to ₹6,000 a month"; technical notes: AiSensy "starts at ₹1,500 a month ... Pass these costs to the client."

The report runs the jugaad test in words but never checks its own price against its own saving. Its small firm price band is not realistic on its own numbers.
